================================================================================
VYSVETLENIE KÓDU PRE OBAJUBU - SIM/eSIM Lifecycle Manager
================================================================================

Tento súbor slúži na to, aby si vedel presne pochopiť každý podstatný kus kódu
a vedel ho obhájiť na prezentácii/obhajobe.

Projekt obsahuje:
- backend/ (Spring Boot 3.3.4, Java 21, Spring Security + JWT, JPA/Hibernate, Flyway, PostgreSQL)
- frontend/ (Angular 22.3, Standalone komponenty, Signal Forms, HttpClient, Guards, Interceptory)
- docker-compose.yml (PostgreSQL)
- README.md (návod na spustenie)

Cieľ: evidovať SIM karty (SimCard) a zákazníkov (Customer), CRUD operácie, prihlasovanie, ochrana routov, validácie, odchyt chýb do DOM (nie do konzoly).

Testovací účet: admin / admin123

2. BACKEND - MODEL (ENTITKY A ENUMY)
================================================================================

2.1 model/SimType.java
----------------------
enum PHYSICAL, ESIM -> typ SIM karty

2.2 model/SimStatus.java
------------------------
enum IN_STOCK, RESERVED, ASSIGNED, ACTIVE, SUSPENDED, TERMINATED -> životný cyklus SIM karty (na demonštráciu stavov)

2.3 model/Customer.java
-----------------------
@Entity -> označuje triedu ako JPA entitu mapovanú na tabuľku
@Table(name="customers")
@Id + @GeneratedValue(strategy = GenerationType.IDENTITY) -> primárny kľúč s autoinkrementom
@Column(nullable=false, unique=true, ...) -> obmedzenia na DB úrovni
@PrePersist -> pred prvým uložením nastaví createdAt/updatedAt
@PreUpdate  -> pri aktualizácii nastaví updatedAt
Gettery/settery -> potrebné pre JPA/Hibernate

2.4 model/SimCard.java
----------------------
@Entity @Table(name="sim_cards")
@ManyToOne(fetch = FetchType.LAZY) -> vzťah N:1 ku Customer (mnoho SIM môže patriť jednému zákazníkovi)
@JoinColumn(name="customer_id") -> cudzie kľúč
@Enumerated(EnumType.STRING) -> enum sa uloží ako TEXT/STRING (čitateľnejšie v DB ako číslo)
@PrePersist nastaví status na IN_STOCK ak nie je zadaný
Väzba customer môže byť null (SIM ešte nie je priradená zákazníkovi)

2.5 model/AppUser.java
----------------------
Tabuľka app_users na autentifikáciu. Obsahuje username, password (BCrypt hash), role.
Používame na overenie pri logine cez Spring Security.

6. BACKEND - BEZPEČNOSŤ, JWT, AUTH
================================================================================

6.1 security/JwtUtil.java
-------------------------
@Component
generateToken(username) -> vytvorí JWT s subject=username, issuedAt, expiration, podpísaný HMAC
extractUsername(token)  -> vyberie username z tokenu
isTokenValid(token, username) -> porovná username + overí expiráciu
Keys.hmacShaKeyFor(...) -> vytvorí SecretKey z app.jwt.secret
Jwts.parser()... -> parsovanie a validácia podpisu

6.2 service/UserDetailsServiceImpl.java
----------------------------------------
implements UserDetailsService
loadUserByUsername(username) -> nájde AppUser v DB, ak nenájde -> UsernameNotFoundException
Vracia org.springframework.security.core.userdetails.User s username, password(hash), kolekciou SimpleGrantedAuthority(role)

6.3 security/JwtAuthFilter.java
-------------------------------
extends OncePerRequestFilter -> spustí sa raz na request
Z hlavičky "Authorization: Bearer ..." extrahuje token
Ak token platný -> vytvorí UsernamePasswordAuthenticationToken a nastaví ho do SecurityContextHolder
Tým sa Spring Security dozvie, že request je autentifikovaný

6.4 config/SecurityConfig.java
------------------------------
@EnableWebSecurity
.csrf(csrf -> csrf.disable()) -> pre REST API bez session formuláru bežne vypnuté
.cors(...) -> povolí volania z http://localhost:4200
.authorizeHttpRequests -> /api/auth/** permitAll, všetko ostatné authenticated
.sessionManagement -> STATELESS (žiadne HTTP session, len JWT)
.authenticationProvider -> DaoAuthenticationProvider s UserDetailsService + BCryptPasswordEncoder
.addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class) -> náš JWT filter ide pred štandardný
PasswordEncoder Bean -> BCryptPasswordEncoder (hashovanie hesiel)

6.5 config/DataInitializer.java
-------------------------------
CommandLineRunner sa spustí pri štarte aplikácie
Nájde používateľa "admin", ak neexistuje vytvorí ho, inak aktualizuje
Vždy nastaví passwordEncoder.encode("admin123") -> zabezpečí správny BCrypt hash (riešenie problému s nesediacim hashom z migrácie)

10.4 core/auth/auth.service.ts

10.6 core/interceptors/auth.interceptor.ts
------------------------------------------

Vezme token z AuthService.getToken()

10.7 core/interceptors/error.interceptor.ts
-------------------------------------------

13. AKO TO VŠETKO FUNGUJE SPOLOČNE
================================================================================

1. Používateľ otvorí http://localhost:4200 -> app.routes presmeruje na /sims
2. authGuard zistí, že nie je token -> presmeruje na /login
3. Prihlásenie cez login formulár -> AuthService.login() pošle POST na /api/auth/login
4. Backend overí cez AuthenticationManager + UserDetailsService + BCrypt -> vráti JWT
5. Frontend uloží token do localStorage
6. Pri ďalších requestoch authInterceptor pridá Authorization: Bearer <token>
7. Backend JwtAuthFilter overí token -> nastaví autentifikáciu do SecurityContext
8. Ak dôjde k chybe -> errorInterceptor ju spracuje a zobrazí cez ErrorService priamo v DOM (error-alert)
9. CRUD operácie cez SimService/CustomerService idú na chránené REST endpointy

14. TIPY NA OBAJUBU
================================================================================

- **localStorage**: "Ukladal som JWT token do localStorage, aby som ho mohol poslať pri každom requeste cez interceptor."
- **auth.guard**: "Chráni chránené routy, bez prihlásenia presmeruje na login."
- **auth.interceptor**: "Pridáva Authorization header ku všetkým requestom okrem prípadu keď token chýba."
- **error.interceptor + ErrorService**: "Chyby zo servera odchytávam, konvertujem na user-friendly text a zobrazujem priamo v DOM cez signal, nie do konzoly."
- **rodič-dieťa (@Input/@Output)**: "V sims-list posielam objekt sim cez @Input do sim-list-item, dieťa cez @Output emituje edit/delete späť rodičovi."
- **Signal Forms**: "Používam Angular 22 Signal Forms – model je `WritableSignal`, schéma s validátormi vznikne cez `form()`, prvky sú viazané cez `[formField]` a chyby zobrazujem cez `field().touched()` a `field().invalid()`. Nie je to klasický Reactive Forms – splnené kritérium je presne Signal Forms."
- **JWT + Spring Security**: "Stateless autentifikácia - žiadna HTTP session, všetko riešené cez token."
- **Flyway**: "Schéma sa nevytvára cez Hibernate, riadim ju migráciami."
- **DTO pattern**: "Neposielam entity priamo, používam Request/Response DTO kvôli bezpečnosti a čistšiemu API."
