8.1 JwtUtil.java

@Value("${app.jwt.secret}") private String secret;
@Value("${app.jwt.expiration-ms}") private long expirationMs;

private SecretKey getSigningKey() {
    return Keys.hmacShaKeyFor(secret.getBytes());
}
-> Vytvorí HMAC-SHA kľúč z nášho tajného reťazca

public String generateToken(String username) {
    Date now = new Date();
    Date expiryDate = new Date(now.getTime() + expirationMs);
    return Jwts.builder()
        .subject(username)      // v claim-e "sub" uložíme username
        .issuedAt(now)          // kedy bol vydaný
        .expiration(expiryDate) // kedy expiruje
        .signWith(getSigningKey()) // podpísanie
        .compact();             // prevedie na reťazec
}

public String extractUsername(String token) {
    return extractClaim(token, Claims::getSubject);
}

public boolean isTokenValid(String token, String username) {
    final String extractedUsername = extractUsername(token);
    return (extractedUsername.equals(username) && !isTokenExpired(token));
}

private Claims extractAllClaims(String token) {
    return Jwts.parser()
        .verifyWith(getSigningKey()) // overí podpis
        .build()
        .parseSignedClaims(token)    // parsuje a verifikuje
        .getPayload();               // vráti claims
}
-> Ak je podpis poškodený/nesprávny, Jwts vyhodí výnimku

9.1 UserDetailsServiceImpl.java
@Service
implements UserDetailsService

@Override
public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
    AppUser appUser = appUserRepository.findByUsername(username)
        .orElseThrow(() -> new UsernameNotFoundException("Používateľ " + username + " nebol nájdený"));
    return new User(
        appUser.getUsername(),
        appUser.getPassword(), // už je BCrypt hash
        Collections.singletonList(new SimpleGrantedAuthority(appUser.getRole()))
    );
}
-> Spring Security volá túto metódu pri autentifikácii. Porovná zadané heslo s hashom cez PasswordEncoder.

9.2 JwtAuthFilter.java
@Component
extends OncePerRequestFilter -> zaručuje, že sa filter vykoná presne raz na HTTP request

@Override
protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain) throws ... {
    final String authHeader = request.getHeader("Authorization");
    String username = null;
    String jwt = null;
    
    if (authHeader != null && authHeader.startsWith("Bearer ")) {
        jwt = authHeader.substring(7); // odoberie "Bearer "
        try { username = jwtUtil.extractUsername(jwt); } catch (Exception e) { /* ignorujeme, token neplatný */ }
    }
    
    if (username != null && SecurityContextHolder.getContext().getAuthentication() == null) {
        UserDetails userDetails = this.userDetailsService.loadUserByUsername(username);
        if (jwtUtil.isTokenValid(jwt, userDetails.getUsername())) {
            UsernamePasswordAuthenticationToken authToken = new UsernamePasswordAuthenticationToken(
                userDetails, null, userDetails.getAuthorities()
            );
            authToken.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
            SecurityContextHolder.getContext().setAuthentication(authToken); // nastavenie autentifikácie
        }
    }
    filterChain.doFilter(request, response); // pokračuje ďalej
}
-> Ak je token validný, užívateľ je považovaný za prihláseného na úrovni Spring Security

9.3 config/SecurityConfig.java

@Configuration
@EnableWebSecurity

@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
        .csrf(csrf -> csrf.disable()) // nepoužívame session cookies na CSRF
        .cors(cors -> cors.configurationSource(corsConfigurationSource()))
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/api/auth/**").permitAll() // login je verejný
            .anyRequest().authenticated()                // ostatné vyžadujú autentifikáciu
        )
        .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        -> ŽIADNE HTTP SESSION. Všetko cez JWT
        .authenticationProvider(authenticationProvider())
        .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class);
        -> Náš filter sa vykoná PRED štandardným UsernamePasswordAuthenticationFilter
    return http.build();
}

11.1 AuthController.java
@RestController
@RequestMapping("/api/auth")

@Autowired/constructor injection -> AuthenticationManager, JwtUtil

@PostMapping("/login")
public ResponseEntity<LoginResponse> login(@Valid @RequestBody LoginRequest request) {
    Authentication authentication = authenticationManager.authenticate(
        new UsernamePasswordAuthenticationToken(request.getUsername(), request.getPassword())
    );
    // authenticationManager použije DaoAuthenticationProvider -> volá UserDetailsServiceImpl -> porovná heslo cez BCrypt
    UserDetails userDetails = (UserDetails) authentication.getPrincipal();
    String token = jwtUtil.generateToken(userDetails.getUsername());
    String role = userDetails.getAuthorities().stream().findFirst().map(a->a.getAuthority()).orElse("ROLE_USER");
    return ResponseEntity.ok(new LoginResponse(token, userDetails.getUsername(), role));
}
-> Ak sú údaje nesprávne, AuthenticationManager vyhodí BadCredentialsException (zachytí sa cez GlobalExceptionHandler ako všeobecná chyba, čo je v poriadku)

13. CEĽKOVÝ TOK (AKO TO VŠETKO FUNGUJE)
================================================================================

PRIHLÁSENIE:
1. Frontend pošle POST http://localhost:8080/api/auth/login {username:"admin", password:"admin123"}
2. AuthController prijme @Valid LoginRequest
3. authenticationManager.authenticate() -> volá DaoAuthenticationProvider
4. DaoAuthenticationProvider volá UserDetailsServiceImpl.loadUserByUsername()
5. Načíta AppUser z DB, vráti UserDetails s BCrypt hashom hesla
6. PasswordEncoder (BCrypt) porovná zadané heslo s hashom -> OK
7. AuthController vygeneruje JWT cez JwtUtil.generateToken()
8. Vráti LoginResponse {token, username, role}
9. Frontend uloží token do localStorage

CHÁNENÝ REQUEST:
1. Frontend pridá hlavičku Authorization: Bearer <token> cez auth.interceptor
2. Request príde na backend
3. JwtAuthFilter sa spustí (pred UsernamePasswordAuthenticationFilter)
4. Extrahuje token, volá jwtUtil.extractUsername() a jwtUtil.isTokenValid()
5. Ak OK -> načíta UserDetails cez UserDetailsServiceImpl a nastaví Authentication do SecurityContextHolder
6. Požiadavka pokračuje do kontroléra (Spring Security vie, že je autentifikovaný)
7. Ak token chýba/neplatný a endpoint nie je permitAll -> Security vráti 401/403

CRUD:
1. Frontend zavolá SimService.create() -> HttpClient POST /api/sims s JSON
2. auth.interceptor pridá token
3. JwtAuthFilter overí token
4. SimCardController prijme @Valid SimCardRequest
5. SimCardService urobí biznis logiku + kontrolu duplicít
6. Uloží cez SimCardRepository (JPA/Hibernate)
7. Vráti SimCardResponse
8. Ak nastane chyba -> GlobalExceptionHandler vráti JSON s message -> error.interceptor zobrazí v DOM

14. ČO SA OPLATÍ NAUČIŤ NA OBAJUBU
================================================================================

NAJVÄČŠIE OTÁZKY SA ZVYČAJNE TÝKAJÚ:

- "Prečo JWT a nie session?" -> Stateless, frontend+backend oddelené, token sa posiela v hlavičke
- "Ako funguje JwtAuthFilter?" -> OncePerRequestFilter, extrahuje Bearer token, validuje, nastaví SecurityContext
- "Prečo DTO a nie entity?" -> Ochrana, čistý kontrakt, menej dát
- "Prečo BCrypt?" -> Heslá sa neukladajú otvorene, jednosmerné hashovanie
- "Prečo Flyway?" -> Verzovanie schémy DB, reprodukovateľné, prehľadné
- "Prečo @ManyToOne LAZY?" -> Efektívnejšie načítavanie, zabráni zbytočným JOIN-om
- "Prečo @PrePersist/@PreUpdate?" -> Automatické časové pečiatky
- "Rozdiel medzi @RestControllerAdvice a @ControllerAdvice?" -> @RestControllerAdvice = @ControllerAdvice + @ResponseBody
